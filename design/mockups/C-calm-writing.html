# 从 0 到 1：渐进式后端入门
写给第一次独立做服务端的你。
## 为什么需要先跑起来
很多人卡在第一步：想把架构想清楚再动手。但后端的复杂度是长出来的，不是设计出来的。先让一个接口能返回正确的 JSON，你对「请求—处理—响应」的理解会比读十篇文章都深。
我的建议顺序是 **路由 → 存储 → 鉴权 → 观测**，每一步都能独立验证，不会出现「改了三小时还起不来」
## 最小可用的一份路由
> 不要过早引入消息队列。——它解决的是你自己制造的问题。
- 单机 SQLite 足够撑到日均 50 万请求
- 先把日志打好，再考虑分布式追踪
- 缓存是优化项，不是地基 `ttl=60`
以 Go 为例，标准库就能写出可维护的分发逻辑，参考 net/http ServeMux 的做法：
1 func router() *http.ServeMux {
2   m := http.NewServeMux()
3   m.HandleFunc("GET /articles/{id}", getArticle)
4   // 先别写中间件，等第二个横切需求出现
5   return m
6 }
